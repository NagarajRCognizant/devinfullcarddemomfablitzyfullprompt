# Business Rules — COPAUA0C (MQ-triggered authorization request processor, CICS trans CP00)

Source: `app/app-authorization-ims-db2-mq/cbl/COPAUA0C.cbl` (1026 lines). Copybooks: `CCPAURQY`
(request message), `CCPAURLY` (reply message), `CCPAUERY` (error log record), `CIPAUSMY`
(PAUTSUM0 segment), `CIPAUDTY` (PAUTDTL1 segment), `PAUTBPCB` (PSB PCB mask), `CVACT01Y`,
`CVACT03Y`, `CVCUS01Y`, `IMSFUNCS`. Trigger: CICS `MQTM` trigger message on queue
`AWS.M2.CARDDEMO.PAUTH.REQUEST`. Reply: `MQMD-REPLYTOQ` of the request (normally
`AWS.M2.CARDDEMO.PAUTH.REPLY`). Data: IMS HIDAM `DBPAUTP0` through PSB `PSBPAUTL`, VSAM
`CARDXREF`, `ACCTDAT`, `CUSTDAT`.

| Rule ID | Rule name | Business statement | Technical basis | Class | Origin | Risk flags |

| BR-01 | Requests are taken from the queue named by the trigger | The request queue to read is the queue named in the trigger event that started the processor. | `1000-INITIALIZE` (230) `EXEC CICS RETRIEVE INTO(MQTM)`, `MQTM-QNAME` → `WS-REQUEST-QNAME` | Control Flow | Business-derived | `NOHANDLE`; if the retrieve fails the queue name stays blank and the open fails |
| BR-02 | The processor waits five seconds for work | A read of the request queue waits up to five seconds for a message before concluding there is none. | `1000-INITIALIZE` line 238 `MOVE 5000 TO WS-WAIT-INTERVAL`, `3100-READ-REQUEST-MQ` `MQGMO-WAITINTERVAL` | Derivation/Default | Hard-coded literal (5000 ms) | Hard-coded wait interval |

## Exception scenarios (MQ and database)

| Condition | Source treatment | Target treatment |
|---|---|---|
| `MQCC-OK` on get | process the message | listener consumes the record |
| `MQRC-NO-MSG-AVAILABLE` | end the run normally | consumer simply waits for the next record |
| any other get failure | log `M003 FAILED TO READ REQUEST MQ`, continue | `MalformedAuthorizationRequestException` / consumer error handler → bounded retry, then DLT |
| open failure | log `M001 REQ MQ OPEN ERROR` | container start failure, surfaced by the health probe |
| put failure on the reply | log `M004 FAILED TO PUT ON REPLY MQ`, continue | outbox row stays unpublished, attempts incremented, republished by the outbox poller |
| IMS `GU` summary not found | normal, use account data | `Optional.empty()` from `AuthorizationSummaryRepository` |
| any other IMS status | log `I002`/`I003`/`I004`, continue | transaction rolls back, record retried then routed to the DLT |
